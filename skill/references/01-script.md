# 01 · 知识点设计与讲稿

## 1. 设计原则

- **一节课 = 一个核心问题**，用整节课回答它。不要堆知识点。
- 知识点按**一条主线**串联（演进、对比、拆解、实战步骤），不是并列罗列。
- 每个知识点用**一个类比**锚定：实习生手册、划重点的考生、说书人、水变蒸汽、修高铁……
- 每页幻灯片 = 一个知识点单元，讲稿 **150~500 字**。
- 一节课的页数参考：实操类 10~15 页，原理类 20~30 页。

## 2. `segments.json` 格式

```json
{
  "segments": [
    {
      "id": 0,
      "chapter": "开场",
      "title": "三个让你心里咯噔一下的现象",
      "subtitle_text": "副标题（可空）",
      "layout": "cards",
      "text": "这一页的完整口播文本，含标点。"
    }
  ]
}
```

硬约束：

- `id` 必须从 0 连续递增，与幻灯片页号一一对应（`build_deck.py` 会断言）
- `text` 是**口播原文**，标点要正确（影响 TTS 的停顿切分）
- `chapter` 会显示在面包屑和导航栏，用**技术名**

## 3. 讲稿口语化规范

| 项 | 要求 |
|---|---|
| 语速 | 250~300 字/分钟（中文口播自然区间） |
| 句长 | 15~35 字，偶尔长句，不要连续长句 |
| 连接词 | 那么 / 然后 / 这里 / 咱们 / 就是 / 对吧 / 是吧 / 你看 |
| 人称 | 统一，全文不要混用「你/您」 |
| 书面语 | 避免「综上所述」「首先其次最后」「值得注意的是」 |

**抛砖引玉**：开场用 2~3 个「你有没有遇到过」的具体现象勾起兴趣，结尾回扣这些现象解释原因。
这是长课留人的关键结构，不要省。

### 表述规范

| 场景 | 说 | 不要说 |
|---|---|---|
| 讲时序图 | 第一步、第二步（步是动作） | 第一条、第二条（条是箭头） |
| 走读代码 | 第一步、第二步（逻辑步骤） | 第一行、第二行（物理行号） |
| 过渡 | 接下来讲第二部分，工具系统 | 回到全景图，这一部分是第二部分 |
| 术语首次出现 | 人工介入才能放行，这叫 HITL，Human In The Loop | 会多一道人点头 |

**过渡语不要念画面。** 观众看得见画面，念一遍等于浪费 3 秒。

**术语第一次出现必须讲全**，第二次开始才可以用缩写。

**压缩式短句要展开**：「混写一改全乱」→「如果混写的话，那么一改就全乱了。所以提示词要分层。」

## 4. 把抽象讲成大白话的四个动作

> 这是长课最常被退回的原因：不是内容错，是**听众在某句话上停下来了**。
> 凡是让人停下来的地方，都是「抽象词 + 没有类比 + 图没标注」。

### 动作一：抽象概念必须配「可数的类比」

判据：**听众能不能用这个类比自己算出一个数**。

| ❌ | ✅ |
|---|---|
| n 个 token 有 n 的平方组关系 | 十个城市两两通高铁要修 45 条；二十个城市要 190 条。城市翻倍，线翻四倍多 |
| 边际收益递减 | 第一碗饭最解饿，第三碗有点撑，第十碗是负担 |

类比要选**听众有生活经验的场景**（修路、吃饭、找钥匙、搬家），不要用行业内的例子。

### 动作二：术语先翻译，再给名字

顺序必须是：**它是什么 → 为什么这么叫 → 举个例子**。

反过来讲（先给术语再解释），听众会卡在第一句。

| ❌ | ✅ |
|---|---|
| 核心就一句话：找到最小的高信号信息集合 | 先说「什么叫上下文工程」→ 拆三个词（信息 / 高信号 / 最小）→ 举例（修 bug：三百个文件 vs 三样东西） |

### 动作三：每个类比都要跟一个真实案例

只有类比没有案例，听众会觉得「道理懂了但不知道用在哪」。

案例必须带**具体数字**：`800 块 / 1024 维 / 0.91 / 600 元`。
数字才是「落地感」的来源，形容词不是。

### 动作四：坐标图必须回答三个问题

每张图都要在图内标清：

1. **横轴是什么**（写全，不要只写 `n`）
2. **纵轴是什么**
3. **每条线各代表什么**（图例写人话）

```
┅┅ 线性 · 加法：字翻一倍，关系也翻一倍
━━ 平方 · 乘法：字翻一倍，关系翻四倍
```

## 5. 章节命名：用技术名，不要包装名

| ❌ 包装名 | ✅ 技术名 |
|---|---|
| 蒙昧 / 借物 / 分层 / 治境 | 第 0 代 · 无记忆 / 第 1 代 · 切块检索 / 第 2 代 · 分层记忆 / 第 4 代 · 上下文工程 |

世界观包装可以用在**标题修辞**里（「六段路，五次破壁」），但**章节名必须是技术名**。
观众看导航是为了知道「现在讲到哪」，不是猜谜。

## 6. 编号一致性：图、讲稿、导航三处必须对齐

常见事故：阶梯图画了 5 代，讲稿讲到「第六代」，而第六章在图上根本没有位置。

落地检查：

```bash
grep -o "第[零一二三四五六七八九十]代" work/segments*.json | sort | uniq -c
grep -o "第[零一二三四五六七八九十]代" work/slides/deck_*.py | sort | uniq -c
```

两边的编号集合必须完全一致。

## 7. 读音相关的写法（送给 TTS 前先改）

### 中文年份用「〇」不用「零」

`二零二三` 会被读成「二十二三」。改用 **`二〇二三`**（U+3007），TTS 逐字读，ASR 会识别成「2023 年」。

### 词组太短会被误读：加长上下文

| ❌ | 现象 | ✅ |
|---|---|---|
| 不省 | 读成 bù xǐng | 不省钱（「省」在「省钱」里必读 shěng） |
| 退出码 | 读成「退出、码」 | 退出码分开 |

规律：单字或双字词在句中被孤立时，模型容易选错读音。**加一个字改变词组边界**，比加拼音注释有效。

### 数字与百分号

`77%` 送 TTS 前要转成「百分之七十七」，`2.0` 这类浮点会被读成乱码。
用 `scripts/num2cn.py` 统一处理，不要在每个脚本里各写一遍。

## 8. 讲稿自查清单

- [ ] 每一页讲稿 150~500 字，没有超过 800 字的页
- [ ] 每个抽象概念，能用一句话类比出来？
- [ ] 每个类比，配了带数字的真实案例？
- [ ] 每张坐标图，横轴/纵轴/每条线的含义都写在图上了？
- [ ] 章节名是技术名？
- [ ] 代际/阶段编号在 deck、讲稿、导航三处一致？
- [ ] 中文年份用「〇」了？短词组加长了？
- [ ] 讲时序图/走读代码时说的是「第 N 步」？
- [ ] 过渡语没有念画面？
