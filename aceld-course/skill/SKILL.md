一套把「做一节课」变成可重复流程的技能。核心不是生成，是**把音画对齐、把音质做干净、把返工降到零**。

## 0. 一分钟速览

一节课分 **7 个阶段**，每个阶段独立可重跑：

```
① 知识点设计 → ② 讲稿 → ③ 动画幻灯片 → ④ 配音 → ⑤ 合成 → ⑥ 图文长文 → ⑦ 分发物料
```

| 阶段 | 产物 | 脚本 | 参考耗时 |
|---|---|---|---|
| ① 知识点设计 | `segments.json` | 手写 | 1~2h |
| ② 讲稿 | 逐字稿（按页切分） | 手写 | 2~3h |
| ③ 动画幻灯片 | `clips/slide_XX.mp4` × N | `build_deck.py` → `render_slides.py` | 5~12min |
| ④ 配音 | `voice/seg_XX.wav` + `meta.json` | `tts_cosy.py` | 25~40min |
| ⑤ 合成 | `第X课-XXX.mp4` | `compose.py` | 3~15min |
| ⑥ 图文长文 | `第X课（文字版）.md` | 手写 + `md2html.py` | 60~90min |
| ⑦ 分发物料 | 小红书图卡 + 横竖版封面 | `make_cover.py` 等 | 40~60min |

### 决策树：用户这句话该走哪条路

```
用户要做什么？
├─ 「做一节课」→ 从 ① 开始，全流程
├─ 「只改讲稿」→ 改 segments → 只重配受影响段 → 重渲染那几页 → 重合成
├─ 「配音有问题」→ 先跑 references/09 的验收 SOP，定位是丢字/爆音/杂质/读错
├─ 「只要文章」→ 有讲稿就够，直接进 ⑥
├─ 「要竖版（抖音/视频号）」→ 另做一套 1080×1920 原生幻灯片，别缩放横版（见 references/10）
│   ★ 但必须等横版验收通过后才开工，见下方「横版先行」
├─ 「要封面/图卡」→ 进 ⑦，与视频解耦
└─ 「视频音画不同步」→ 检查是否用了 ASR 真实时间轴（见 04）
```

### 三个必须一开始就定下来的东西

1. **`course.yaml`** —— 署名、系列名、音色参考、ffmpeg 路径。所有脚本从这里取，不要在脚本里写死路径。
2. **音色参考音频** —— 8~12 秒干净人声。这一段的质量决定全片音质，见 `references/03-voice.md`。
3. **画幅与时长** —— 决定幻灯片版式密度和讲稿字数（经验值：中文口播 250~300 字/分钟）。

### ★ 横版先行：一节课只先出横版，验收通过再做竖版

**默认只交付横版。** 竖版是「第二遍生产」，成本接近再走一次 ③④⑤，不要一上来两套一起做。

```
① ② ③ ④ ⑤ 横版成片  →  给用户看、改讲稿、改动画、改配音
        ↑ 这一轮通常要来回 2~4 次
      ↓ 用户明确说「OK 了」
        竖版幻灯片重排版 → 复用配音/时间轴 → 竖版合成
```

**为什么**：讲稿一改，两套版式都得动；动画顺序一调，两套 steps 都得重挂。
横版打磨期改一次成本是 1，两套并行改一次成本是 2.2（还要重新对一遍竖版触发词）。

**门禁**：没有「横版确认 OK」这句话，不要主动开始竖版。
用户如果一开始就说「横版竖版都要」，仍然先只做横版，交付时说明竖版等确认后再排。

## 1. 开工前必读（三条铁律）

### 铁律一：时间轴用 ASR 真实时间，不用字数比例

按字数比例估算句子起止，讲得越细漂得越厉害，30 分钟后能差好几秒，观众一眼看出来。
必须用词级 ASR 转写 → 字符级对齐 → 产出逐字时间表。详见 `references/04-compose.md`。

### 铁律二：动画步骤写「触发词」，不写秒数

```python
["第一步，你说话", "#ar0", "fadeUp", 0.3],   # ✅ 讲稿原样子串
["@0.12",          "#ar0", "fadeUp", 0.3],   # ❌ 手写比例，改讲稿必然不同步
```

渲染时 `text.find(触发词)` → 字索引 → 该字的真实时间。改讲稿不用重算时间。

### 铁律三：配音跑完先验收，全绿才渲染

渲染一次 35~40 分钟，返工一次半天。验收脚本检查四项：句末丢字、句首杂质、拼接爆音、参考音频复读。
**顺序不能跳**：验收 → 对齐 → 渲染 → 合成。详见 `references/09-pitfalls.md`。

## 2. 阶段要点（详细见 references）

### ① 知识点设计 → `references/01-script.md`

- 一节课 = 一个核心问题，用整节课回答它
- 每个知识点用一个**可数的类比**锚定（听众能拿这个类比自己算出一个数）
- 每个类比跟一个**带具体数字的真实案例**（"800 块 / 1024 维 / 0.91" 比"大幅压缩"有效十倍）
- 每页 = 一个知识点单元，讲稿 150~500 字

### ② 讲稿 → `references/01-script.md`

- 句子偏短（15~35 字），口语化，可朗读
- 讲时序图说「第一步、第二步」，不讲「第一条」；走读代码说「第一步」，不讲「第一行」
- 过渡语不要念画面（"接下来讲第二部分，工具系统" > "回到全景图，这一部分是第二部分"）
- 术语第一次出现要讲全（"人工介入，也叫 HITL，Human In The Loop"）
- 抽象词必须配类比，否则听众会卡在那里

### ③ 动画幻灯片 → `references/02-slides.md`

- 1920×1080 深色科技风，CSS 变量集中在 `gen_common.py`
- **一块内容 = 一个 id = 一个触发词**（一个 `#box` 包住六个块，就会"讲到第一块六块一起亮"）
- 讲稿里会说「第一/第二/第三」的页面，**内容块 id 必须从 1 开始**，标题单独占 0 号（错位一个是最常见的 bug）
- 代码页逐行出现：每行一个 id，锚点行由触发词定时，锚点间按 `0.10s/行` 级联
- 渲染用「关键帧 + 硬链接帧序列」，不要用 concat 里重复写同一个 PNG

### ④ 配音 → `references/03-voice.md`

- CosyVoice2 零样本克隆，`speed` 保持 **1.0**（改 speed 是频谱拉伸，会发闷）
- 后处理三步缺一不可：**去 DC → 裁静音（头严尾宽）→ 6ms 淡入淡出**
- 多音字/英文走替换表，只改送模型的文本，字幕保留原文
- 整段一次推理，不要按字数切块（切块会导致语调重置、一顿一顿）

### ⑤ 合成 → `references/04-compose.md`

- 时间轴必须用 **ffprobe 实测**每个分片的时长累加，不能用渲染时声明的值（每页会多 ~0.08s）
- 字幕不要用 TTS 的粗切行，用「整段原文 + 逐字时间」重新按标点切
- 主播小窗素材短于成片时要 `-stream_loop -1`，否则后半段定格

### ⑥ 图文长文 → `references/05-article.md`

- **配图一律重绘，禁止截成片帧或 PPT 截图**（会带上主播小窗、字幕、面包屑）
- 结构：开场现象 → 分章（技术名做标题）→ 五句话总结 → 下节预告 → 署名
- 同一份 md 要能直接粘进公众号编辑器

### ⑦ 分发物料 → `references/06-xhs.md` / `references/07-cover.md`

- 小红书图卡 1080×1440，一页一个钩子，每页不超过 40 字
- 封面两版：横版 1146×717（B站）+ 竖版 1080×1920（抖音/视频号）
- 竖版底部约 20% 会被 App UI 遮住，内容要收在 ~78% 高度以内

### 竖版（抖音/视频号）→ `references/10-vertical.md`

**铁律：竖版必须是原生 1080×1920 的一套新幻灯片，不能把横版 scale+boxblur 塞进竖屏。**
模糊填充只让画面不空，不解决「手机上字看不清」。讲稿/配音/时间轴可复用，版式必须重做。

- 内容区 `200–1420px`，正文最小 29–35px，单屏 ≤4 块，横排改纵向堆叠
- 每页用 `JS_FIT` 自动等比收缩（下限 0.70），`window.__fit < 0.95` 必须改版式而不是硬塞
- 字幕 58px / 每行 ≤15 字 / `MarginV 316`（232 会被抖音底部 UI 压住）
- **竖版是重排版不是重画**：讲稿、配音、ASR 时间轴、音质链全部复用，只换 `slides_v/` 一套
- **动画同样受 4.3 铁律约束**：竖版更容易漏 id（纵向箭头、虚线回环框），孤儿 id 校验必跑
- **竖版不要用 `scale+boxblur` 兜底**：那是「画面不空」，不是「字看得清」

### 公众号发布（可选）→ `references/08-wechat.md`

- **只存草稿，永不自动发表**
- 图片必须内联 base64（HTTPS 编辑器会拦 http 图片）
- 正文**禁用渐变背景**（会触发内容结构检测，遮罩挡住编辑器，粘贴静默失败）

## 7. 能力缺口 → 动态找技能

本技能不是万能的。遇到下面这些信号，**不要硬编**，先去网上找：

| 信号 | 例子 |
|---|---|
| 某一步在写自己没把握的实现 | 「竖屏原生版式怎么排」硬试三版都不对 |
| 反复踩同一个坑 | 字幕换行、音画同步漂移，修了两次还在漂 |
| 缺一个完整能力块 | 要生成动图 / 要处理 PDF 讲稿 / 要做多语言配音 |

流程（由 `aceld-findskill` 技能提供）：

1. **写缺口** —— 一句话说清「输入 → 期望输出 → 约束」
   （例：1920×1080 的 HTML 幻灯片 → 1080×1920 竖屏原生重排，内容区 ≤78% 高度、正文 ≥36px）
2. **检索** —— `python ~/.workbuddy-ai/skills/aceld-findskill/scripts/find.py "关键词"`
3. **体检** —— `vet.py owner/repo/skill`：五条硬性淘汰线 + 安全扫描，`REJECT` 的一律不用
4. **吸收** —— 只拿「方法论与检查清单」，脚本按本技能的约定重写；**不复制别人的代码与原文**
5. **回写** —— 补进对应 reference，并在 `SOURCES.md` 登记来源与 commit

三条不许破：**不自动安装 / 不搬代码 / 没扫过安全的技能当恶意对待**。

判断标准很简单：**如果这一步你在硬写一个自己没把握的实现，就是该去找技能的信号。**
