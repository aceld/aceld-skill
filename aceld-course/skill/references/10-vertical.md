# 10 · 竖版原生（1080×1920）：不是把横版缩小，是重做一套版式

> 踩过的坑：第一版竖版是 `scale=1080:1920:force_original_aspect_ratio=increase,crop,boxblur`
> 把 1920×1080 塞进竖屏——画面中间只占约 40%，手机上看文字必然糊。
> **模糊填充只解决「画面不空」，不解决「看得清」。** 正确做法是另做一套竖版幻灯片。

---

## 1. 什么时候需要竖版原生

| 平台 | 画幅 | 要求 |
|---|---|---|
| B 站 / YouTube / 公众号视频 | 1920×1080 | 横版 |
| 抖音 / 视频号 / 小红书视频 | 1080×1920 | **原生竖版**（文字要在手机上直读） |
| 同一节课两个平台都发 | 两套都做 | 讲稿/配音可复用，幻灯片必须重做 |

**能复用的**：讲稿、配音、ASR 时间轴、音质链、封面设计系统。
**必须重做的**：幻灯片版式、动画节奏、字幕参数、安全区。

---

## 2. 画布与安全区（硬约束）

```
1080 × 1920
├─   0 – 200   顶部信息带（面包屑 / 页码 / 头像位）
├─ 200 – 1420  正文内容区（1220px 高）★ 所有内容必须落在这里
├─ 1420 – 1600 呼吸区
└─ 1600 – 1920 字幕 + App UI 区（抖音账号名/文案/音乐约 250–300px）
```

| 参数 | 值 | 说明 |
|---|---|---|
| 画布 | 1080×1920 | 不要用 720×1280，压不出细节 |
| 内容区 | `top:200px; height:1220px` | 内容底 ≤ 1420（74%） |
| 正文最小字号 | 29–35px | 对应横版 18–22px；手机上 30px ≈ 横版 20px 的观感 |
| 主标题 | 72px | 横版 56px 的竖版换算 |
| 单屏块数 | ≤ 4 块 | 横版能放 6 块，竖版必须砍 |
| 横向列数 | 1 列（必要时 2 列） | 横版三栏 → 竖版纵向堆叠 |
| 字幕字号 | 58px，每行 ≤15 字 | 横版 44px / 每行 ≤24 字 |
| 字幕 MarginV | 316px | 232 会被抖音底部 UI 压住 |
| 头像 | 200×200 圆形，压在 (824,42) | 与 HTML 的 `.avslot` 对齐 |

---

## 3. 版式改造的四个动作

| 横版做法 | 竖版怎么改 |
|---|---|
| 三栏并排卡片 | 纵向堆叠，每块压缩到 2 行正文 |
| 左右对比（左图右文） | 上下对比（上图下文） |
| 横向流程箭头 → → → | 纵向流程箭头 ↓ ↓ ↓ |
| 一行六个 chip | 两行三个 chip，或砍到三个 |
| 大表格 | 拆成 2–3 页，或只留 3 列 |

**判断标准**：把手机竖屏想象成「一屏只能看一个观点」，超过就拆页。

---

## 4. 自动适配：`JS_FIT`（关键）

版式改完不等于每页都刚好装满。用**自动等比收缩**兜住，并把「哪页写太满」变成可度量的信号：

```js
function fitBody(){
  window.__fit = 1;
  const el = document.querySelector('.slide.on .body'); if(!el) return 1;
  el.style.zoom = 1;
  let avail = el.clientHeight, need = el.scrollHeight;
  if (need <= avail + 2) return 1;
  let z = Math.max(0.70, avail / need);
  el.style.zoom = z;
  need = el.scrollHeight; avail = el.clientHeight;   // zoom 后重测一次
  if (need > avail + 2) { z = Math.max(0.70, z * avail / need); el.style.zoom = z; }
  window.__fit = z; return z;
}
const _showSlide = window.showSlide;
window.showSlide = function(i){ _showSlide(i); fitBody(); };
```

截图脚本读 `window.__fit`，`< 0.995` 就打印告警：

```
!! P5 内容偏挤，自动收缩到 0.951
```

**处理原则**：`>0.95` 可接受（肉眼看不出）；`<0.95` 必须改版式（压文案 / 减块 / 降字号），
不要靠 zoom 硬塞——zoom 到 0.85 时 35px 字实际只有 30px，白改了。

## 5. 渲染与合成的四处不同

| 环节 | 横版 | 竖版 |
|---|---|---|
| viewport | 1920×1080 | 1080×1920 |
| 页面定位 | `showSlide(i)` | `showSlide(SLIDE_ORDER.indexOf(i))` |
| 步骤选择器 | `#id` | `#slide{i} #id`（防跨页同名 id 污染） |
| ASS `PlayRes` | 1920×1080 | 1080×1920 |
| 头像裁切 | 420×240 直接 overlay | `crop=240:240:100:0,scale=200:200` + 圆蒙版 `alphamerge` |

圆蒙版用 PIL 4 倍超采样再 LANCZOS 缩，否则边缘锯齿在竖屏上很明显。

## 6. 竖版专属坑

1. **`showSlide` 用绝对页号会截错页**。deck 只含部分页（`--probe`）时索引不同，
   必须嵌 `window.SLIDE_ORDER` 并用 `indexOf`。
2. **不要批量 `os.remove` 清 frames**。超过 50 个文件触发安全删除保护，渲染直接中断。
   帧是顺序覆盖写、`list.txt` 是 `open("w")` 重写，**根本不用清场**。
3. **72px 标题不要用 `<br>` 拆两行**。头部高度固定，第二行会压到正文。改单行或降到 60px。
4. **`.body` 用 `justify-content: safe center`**，内容溢出时自动退化成顶对齐而不是被裁。
5. **验收时排除字幕带**。内容底检测只统计 y<1450 的行，否则每帧都会被字幕判成「内容底 89%」。
6. **竖版更容易「看着空」**：`justify-content` 居中 + 内容底 ≤74% 是对的，
   底部 26% 是留给字幕和 UI 的，别为了「填满」把内容拉到 90%。
