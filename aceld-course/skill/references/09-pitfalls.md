# 09 · 踩坑总表与交付验收 SOP

> **做新课必读。** 这一章不是知识点，是别人已经替你踩过的坑。
> 一条一条过，能省掉一轮完整的返工。

## 一、踩坑总表

### 1.1 音画同步

| 坑 | 后果 | 对策 |
|---|---|---|
| 用字数比例估算句子时间 | 越讲越漂，30 分钟能差几秒 | 用 ASR 词级转写 + 字符级对齐 |
| 动画步骤写 `@0.12` 这种手写比例 | 改一次讲稿就全部不同步 | 写讲稿里真实存在的触发词 |
| 合成用渲染时声明的 `dur` | 每页多 0.08s，30 页累计 2.2s | 用 `ffprobe` 实测时长累加 |
| 局部重渲染复用旧 timeline | 重排后 `old[i]` 指向另一页 | 对跳过的页 `probe_dur(现有 clip)` |
| 改了讲稿文字但没重渲染该页 | `pad = vid - aud` 算出负数，整体错位 | 改文字 = 该页必须重渲染 + 重合成 |

### 1.2 语音

| 坑 | 后果 | 对策 |
|---|---|---|
| 淡出用 28ms | 句末轻声被削掉，38/42 段「最后几个字没了」 | **6ms** |
| 静音裁剪尾部阈值 0.08 | 同上，系统性丢字 | 尾部单独用 `0.015 + 40ms` |
| 静音裁剪头部阈值 0.02 | 句首一声「杂质」 | 头部 `0.08` + 连续 3 帧超阈值 |
| 不做去 DC / 不做淡化 | 拼接点波形阶跃 → 「啪」爆音 | 去均值 → trim → 6ms 淡化，缺一不可 |
| 按字数切块独立推理 | 每块语调重置，一段一段的 | 整段一次推理，块间静音 0.12s |
| 词间空隙归零（停顿门） | 字与字被硬切，一顿一顿 | 不做任何词间静音处理 |
| 改 `speed` 来降速 | 频谱线性拉伸，0.6 发闷且调不回来 | **speed 永远 1.0**，靠讲稿控制节奏 |
| 用 `cross_lingual` 读英文 | 音色和韵律一起漂 | `zero_shot` + 音译替换表 |
| 参考音频尾部有杂音/硬切 | 每句结尾冒出固定的怪音 | 用词级 ASR 卡切点，末尾留 130ms |
| 事后打补丁清怪音 | 每清一轮又冒新的 | 换干净的参考音频，治本 |
| `wetext` 没装 | 数字/英文裸奔进 tokenizer，全乱 | `pip install wetext` |
| 用「相邻样本差 > 0.08」查爆音 | 正常塞音/擦音全误报（17s 报 94 处） | 只看长静音边界，`> 0.03` 才算 |
| 比较原文与 ASR 时不先去标点 | 误判丢字 15~20% | 两边都去标点再比 |
| faster-whisper 传 numpy 不重采样 | 2.7 倍快放，ASR 全乱码 | 自己重采样到 16k |

### 1.3 幻灯片

| 坑 | 后果 | 对策 |
|---|---|---|
| id 打在容器上 | 讲到第一块，六块一起亮 | 一块内容 = 一个 id = 一个触发词 |
| 只给部分子元素打 id | 有的块永远不出来 | 所有 `id=` 和 steps 做差集，必须为空 |
| 内容块 id 从 0 开始，讲稿说「第一块」 | 每个模块都提前一个 | 标题占 0 号，内容从 1 开始 |
| 触发词未命中不报错 | 静默退回「均匀铺开」，动画全乱 | 单独跑命中检查，必须 0 条 |
| 触发词用段尾总结句 | 图到最后一秒才出来，等于没动画 | 用该内容**第一次被提到**的词 |
| `draw` 用在虚线上 | 虚线被渲染成实线，和讲稿打架 | 虚线用 `fadeIn`，实线才用 `draw` |
| `hl` 用在整块 card 上 | 刺眼黄框 | 只用于代码行 |
| `hl` 没设 opacity | 被 `resetAll()` 置 0 后永远不可见 | 加进 `NOHIDE` 集合 |
| concat 里重复写同一个 PNG | `DTS ... invalid dropping`，clip 只剩 4 帧 | 硬链接帧序列 |
| 用 `-vsync` | ffmpeg 5+ 已移除 | `-fps_mode cfr -r 30` |
| 彩色 emoji 在无头 Chrome | 退化成白色剪影 | 改用「中文字牌」 |
| 预览脚本选择器没加 `#slide{i}` | 跨页同名 id 互相污染 | 加前缀 |
| 内容全堆在上半屏 | 版式失衡 | `.inner` 加 `justify-content:center` |
| **★装饰元素没 id**（箭头/红字标题/整改卡/虚线框） | **「有的先出来了」——用户最高频投诉**，语音没讲到画面已满 | 看得见的元素必须能回答「我在哪个 step 里」，答不上就是下一个 bug |
| `draw` 用在整段竖线上 | 渲染后只剩箭头，线不见了 | 曲线才用 `draw`；竖线改「线常驻 + 节点卡片逐个 fadeUp」 |
| 竖版 `head()` 的 `eid=None` | 每页 steps 的 `#eb` 全成孤儿，27 页报 27 条失败 | `eid` 默认值设 `"eb"` |
| 竖版 `.body` 用 `safe center` | 内容整体偏上，看着「上挤下空」 | 用 `center` + `padding-bottom:20px` |
| 一上来横版竖版并行做 | 讲稿改一次要动两套版式 + 两套触发词 | 横版验收通过后才开竖版（SKILL「横版先行」） |

### 1.4 合成与出片

| 坑 | 后果 | 对策 |
|---|---|---|
| `-loop 1` overlay 没带 `shortest=1` | 输出永不结束（36 分钟源编到 1 小时+） | `overlay=0:0:shortest=1` + `-shortest` |
| 主播素材短于成片 | 后半段定格成照片 | `-stream_loop -1`（放在对应 `-i` 之前） |
| 字幕用 TTS 的粗切行 | 断在词中间（「么该丢。」） | 用整段原文 + 逐字时间重新切 |
| 竖版直接 crop | 架构图/表格两侧被切掉 | 重排版（见 references/10），不要 crop |
| **把模糊填充当竖版方案** | 画面只占中间 40%，手机上字看不清 | 模糊填充只做过渡；正解是原生 1080×1920 重排版 |
| 用 `sidechaincompress` 做 de-esser | 抽吸产生「拉链声」，听感是刺耳噪音 | numpy 平滑去齿音 |
| 只靠肉眼看单帧验收 | 看不出「定格」「没亮」 | 隔 1 秒取两帧算像素差 / 像素统计 |
| 看图工具返回缓存图 | 误判渲染全错，白改一轮 | 用像素统计代替肉眼看图 |

### 1.5 内容与交付

| 坑 | 后果 | 对策 |
|---|---|---|
| 章节名用包装名 | 观众不知道「讲到哪」 | 章节名用技术名，包装放标题修辞 |
| 图、讲稿、导航三处编号不一致 | 讲到「第六代」但图上没有 | grep 一遍编号，三处对齐 |
| 代码页只给 3 处触发 | 一开场全部显示，等于没动画 | 每行一个 id，按行给触发词 |
| 过渡语念画面 | 浪费 3 秒 | 「接下来讲第二部分」 |
| 术语首次出现用缩写 | 听众卡住 | 第一次讲全，第二次才用缩写 |
| 结尾页放二维码 | 部分平台限流 | 删掉 |
| 文章配图截成片帧 | 带上小窗/字幕/面包屑，掉档 | 全部重绘 |
| 竖版封面内容贴底 | 被 App UI 盖住 | 收在 78% 高度以内 |

### 1.6 发布与平台

| 坑 | 后果 | 对策 |
|---|---|---|
| 正文用渐变背景 | 弹「内容结构检测」，粘贴静默失败 | 一律纯色底 |
| 残留模态框 | 下次粘贴被遮挡 | 关弹窗 + reload 再粘 |
| 粘贴后不校验 `imgs` | 空文章覆盖好草稿 | `imgs > 0` 才允许保存 |
| 图片走本地 HTTP | HTTPS 编辑器拦截（混合内容） | 内联 base64 |
| 编辑器 URL 没带 token | 「请重新登录」 | 从已登录标签页抓 token |
| token 写死 | 轮换后全部失效 | 每次重新抓 |
| 首屏二维码误判为掉登录 | 让用户白扫一次 | 看重定向后 URL 有无 token |
| `#title` 用 `locator.click()` | 元素不可见超时 | JS 设值 + 派发事件 |
| 查正文用第一个 `.ProseMirror` | 误判「正文是空的」 | 用 `#ueditor_0 .ProseMirror` |

### 1.7 环境

| 坑 | 对策 |
|---|---|
| Windows 上 `python.exe` 被应用控制策略按哈希拦死 | 用同版本 `pythonw.exe`，改名/复制无效 |
| 沙箱批量删除保护（`shutil.rmtree` 报错） | 逐文件 `os.remove` |
| HF 下载后 snapshots 是 0 字节软链 | 把 blobs 复制回 snapshots |
| 某些 DLL 被随机拦截（numpy/pyarrow/numba/pyexpat） | 重试通常恢复 |
| ffmpeg 不在 PATH 上，pydub 找不到 | 显式注入 `PATH` + `FFMPEG_BINARY`/`FFPROBE_BINARY` |
| Chrome DevTools 用默认 profile 拒绝启动 | `--user-data-dir=<非默认目录>` |
| shell `&` 起的后台进程被杀 | 用任务管理器的后台模式 |

## 二、★交付前自动验收（配音跑完立刻跑）

**顺序不能跳**：验收 → 对齐 → 渲染 → 合成。

```python
# ① 句末丢字
#    ASR 全文 vs 原文，两边都去标点后逐字比对
#    判定：连续 2 字以上缺失且非英文/数字 → 真丢字

# ② 句首杂质
for a, b in long_silences:                     # 长静音 >= 0.4s
    pk = abs(x[b*win : b*win + int(sr*0.06)]).max()
    if pk < 0.15:                               # 真语音应该 0.15~0.9
        report("句首杂质", a)

# ③ 拼接爆音
pre, post = abs(x[i0-1]), abs(x[i1])
if pre > 0.03 or post > 0.03:
    report("拼接爆音", i0)

# ④ 复读
#    准备「参考音频独有词」清单，ASR 转写后看是否命中
```

**抽验必查的 3 类段**（不用全跑 ASR）：

1. 含最多英文词的那段
2. 含句末轻声最多的那段
3. 含多音字的那段

**渲染后再抽**：

- 抽 3 帧：封面页 / 代码页 60% / 结尾页
- 抽 2 段音频：开头 / 英文段
- `ffprobe -count_frames` 核对帧数 = 时长 × 30

## 三、时间账

| 环节 | 一次做对 | 返工一次 |
|---|---|---|
| 讲稿 | 2~3h（人工，瓶颈） | 2~3h |
| TTS 40 段 | 25 min | 25 min |
| ASR 对齐 | 15 min | 15 min |
| 渲染 40 页 | 35 min | 35 min |
| 合成 | 10 min | 10 min |
| **合计** | **~85 min（不含讲稿）** | **~85 min + 等待 + 沟通成本** |

真实案例：某节课在语音上返工 8 轮、约 12 小时，其中 6 轮本可以一次做对。
**如果一开始就跑第二节的验收，至少省 6 轮。**

## 四、开工顺序（照这个走，不要跳）

```
1. 定 course.yaml（署名 / 系列名 / 音色参考 / 路径）
2. 写 segments.json → 跑发音替换预览，确认多音字/英文都命中
3. 写页面定义 → build_deck 校验（触发词命中 + id 全覆盖）
4. 全量 TTS
5. ★跑验收（第二节）→ 全绿才继续
6. align_asr → render_slides → compose
7. 抽帧 3 张 + 抽音频 2 段
8. 交付；需要的话再做文章 / 图卡 / 封面
```

## 五、验收清单（打印出来对着打勾）

- [ ] 编号三处一致

- [ ] 触发词全部命中
- [ ] 所有 id 都被 step 用到
- [ ] 虚线没用 `draw`
- [ ] 坐标图三条信息都标了
