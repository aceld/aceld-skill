# Aceld 架构图风格指南（绘图规范）

> 本指南提炼自刘丹冰（Aceld）的真实架构图作品——鹰眼二期存储优化方案、KisFlow 整体结构等
> `.drawio` 源文件与导出图。通过解析源文件中的 `fillColor` / `strokeColor` / `fontColor` /
> `shape` 属性分布，沉淀出他实际使用的 **draw.io 默认主题配色与图形语言**，而非主观想象。
> 生成器见 `scripts/gen_diagram.py`，可直接复刻这套风格。

---

## 一、一句话定位

Aceld 的架构图是**工程架构师的「draw.io 默认主题」白底扁平风**：
**纯白底、扁平、无渐变无阴影、圆角矩形模块 + 圆柱存储 + 虚线分组 + 便签标注 + 细线小箭头**。
颜色来自 draw.io 内置调色板，同一种语义用同一种色；讲究一眼读懂结构与数据流，不追求花哨。

| `slate`  | `#647687` | `#314354` | 白 | 控制器等（实心石板蓝） |
| `dark`   | `#36393d` | `#000000` | 白 | 深色块/标题条 |
| `white`  | `#FFFFFF` | `#36393d` | 黑 | 默认白底模块 |

**规则**：
- 颜色只做**分类**，同一种语义全图同色；不要为了好看乱选。
- **实心深色框**（blue / orange / slate / sgreen）→ 白字；**浅色框**（lblue / green / red / yellow / purple / gray）→ 黑字。生成器按亮度自动选字色。
- 描边一律 **1px**，且取该填充的对应深一档同色系（如蓝填充配 `#006EAF`）。
- **同一张图只在一种色系内选，且优先全实心重色**：推荐统一用实心重色（blue / orange / slate / sgreen / crimson / dark），白字、视觉更整；若用浅色则必须全浅色。**深浅绝不混搭**——实心蓝/橙框与浅绿/浅蓝框不能同框出现（否则一眼显乱）。重色块之间允许同色系重复（如多个算子同橙），靠分组框与层级虚线分隔区分，不靠换色。

## 三、核心特点（提炼清单）

1. **纯白底 + 扁平 + 蓝图感，零装饰**
   背景 `#FFFFFF`，无渐变、无阴影、无 3D。整张图靠「结构 + 颜色 + 连线」说话。

2. **圆角矩形模块（`rounded=1` 为主）**
   绝大多数是圆角矩形（`rx≈8`），1px 描边，文字居中、无衬线、中英混排
   （如 `Flow 数据流`、`Scheduler 调度器`、`Redis 缓存`）。这是图的主体。

3. **数据库一律用圆柱（`cylinder3` / `datastore`）**
   MySQL、Redis、日志存储等用 draw.io 圆柱形状，浅色填充 + 同色描边，一眼区分「存储」与「计算」。

4. **虚线分组括号 + 标题 + 浅色底（`curlyBracket` / `dashed`）**
   相关模块用**浅色底 + 同色虚线圆角框**圈起来并加标题（如 `Function 算子池`、`调度核心`、`外部依赖`）。
   分组即语境，标题写在框左上角（生成器会在标题下垫同色底，避免被连线压住）。
   浅色底是「层级感」的关键：不同分组用不同色相的极浅色（暖橙 / 冷蓝 / 浅红），一眼区分层次。
   **所有分组默认统一为等宽层带**（取并集的左右界），上下堆叠成整齐的横向分层，不会一大一小。

5. **层级虚线分隔（`tiers`，可选）**
   当要表达「当前图分了几层 / 每层是什么」时，用**贯穿全图的横向虚线**把层级划开，
   虚线左端写**加粗的层级名 + 一句话说明**（如 `算子执行层 · 算子可插拔、配置热更新`）。
   它与分组框不同：分组框是「圈住一组实体」，层级虚线是「在层与层之间画一道分界并配文字描述」。
   **注意**：层级标签画在最左侧，需要左侧留白；若图没有左列、内容又左对齐，标签会压到内容上。这种图**优先用分组带的「浅色底 + 标题」来分层，省略 tiers**（分组带本身已是虚线分层 + 文本描述）。

6. **便签（note）做标注**
   补充说明、设计要点用 draw.io 的便签形状（右上折角的小方块）贴在一旁，浅黄底。

7. **左侧跨维度列（可选，非默认）**
   若整张图确有「跨维度的全局模块 / 关注点」（如全局配置、可观测监控、安全、统一接口层），可在最左侧用一条**纵贯全图的竖条**承载其标签（逐字换行、不旋转、不溢出框外）。
   **注意：这不是必备元素，更不是每张图都要加。**「鹰眼」只是鹰眼二期那一张图里竖条的具体名字（代表全链路可观测）；换一张图就换成该图自己的跨维度模块名，**或干脆不加**。切勿把「鹰眼」当成 Aceld 风格的固定符号到处贴。

8. **正交连线 + 小三角箭头（`flexArrow` / `singleArrow`）**
   连接线略粗（约 2.2px）、箭头小而克制；走**正交折线（直角 / 圆角）**。
   - **路由原则（关键）**：两个模块**上下分离**时，连线**竖直**从上方盒底出、竖直进入下方盒顶（A 在 B 上方就竖进竖出，不要从侧边横着绕）；**同行并排**时才横进横出。斜向错位时优先竖直。
   - **能直连就不折（2026-11-05 定）**：两盒上下对齐（x 区间有交集）→ **一条竖线直达目标盒顶**，不要「竖下 → 横挪一点 → 再竖下」；并排且 y 区间有交集 → 一条横线直达。允许折的只有三种：两盒斜对角完全错开、同一条边挂多条线必须错开端口、显式 `via` 绕开节点。路径里的共线冗余拐点一律合并——那不是折线，是毛刺。
   - **端点留隙**：线头离边框 3px、箭头端离目标边框 8px，**整支箭头落在盒外**，既不压边框也不被遮挡。显式 `via` 的目标端同样留 8px（曾只留 3px，箭头尖贴着盒边被描边吃掉）。
   - **主体线在盒下，箭头层在最上（2026-11-05 定）**：连线主体画在**节点之下**（跨过无关矩形时被盒子自然遮住，不盖模块）；但节点、连线标签白底、分组虚线框与标题、便签、图题全都在主体线之上，箭头跟着主体线走必然被压掉。因此把「末段 18px + 箭头」拆成独立一层，放到所有元素之后重画。**任何元素压住箭头都算错**；遮挡严重时优先挪开遮挡物，不是把箭头缩回盒里。
   - **端口分配**：同一节点的同一条边挂多条线时，自动按对端位置均匀错开，避免两根线重叠、箭头被压。
   - **避开禁线**：折点位置自动避开分组虚线边与层级分割线（不与之重合）；端口若贴在分组左右边也会自动挪开。
   - **跨线留白**：逐条「白色光晕（7px）→ 彩线」绘制，后画的线在交叉处切断先画的线，形成「跨线桥」。
   - **标签避让**：连线文字自动避开节点、分组标题与其它标签，绝不互相覆盖。
   - 实线表主数据流，虚线表控制/依赖关系（如 `调度`、`管理`、`连接`）。

9. **中英混排、无衬线、居中**
   所有文字用 Helvetica/Arial/PingFang/微软雅黑 之类无衬线；模块名常见「英文 + 中文」组合并居中。

10. **自由摆放，多图岛**
   模块是**手摆坐标**而非自动布局；一张图里常有多个相对独立的小图岛（子系统），靠分组框区分。

11. **流程步骤可用 chevron / step 形状**
    顺序处理链有时用 `step`（折角箭头块）或 `doubleEllipse`（起止圆）表达，增强顺序感。

## 四、什么时候用这种图

- 系统/模块**架构总览**（一眼看全栈与依赖）
- **数据流 / 处理链路**图（顺序算子、调度、存储）
- 架构**演进 / 路线图**
- 给**工程师 / 技术评审**快速讲清「怎么跑、数据去哪、哪里是关键节点」

**版式（横版 / 竖版）**：默认**竖版**。文档大多「高度不限、宽度有限」，竖版（约 4:5 ~ 3:4，如 923×1246）更适合嵌入文章 / 讲义，不会被横向裁切。
需要横向大屏（PPT 整页、宽屏）时再出横版。竖版做法：缩窄模块宽度、拉大层间纵向间距、存储放最底部横向一排；拓扑与横版一致。
示例见仓库 `examples/kisflow_arch_portrait.json`（竖版）与 `examples/kisflow_arch.json`（横版）；
本地安装版只装 `skill/` 子目录，不含 `examples/`，需要时去仓库取。

**先选图种，再动笔**（四种图共用同一套视觉，见 §十一）：

| 要回答的问题 | 用哪种图 |
|---|---|
| 系统有哪些模块、谁依赖谁、分几层 | 架构图（`gen_diagram.py`） |
| 一次调用按什么顺序穿过组件、谁调用谁、何时返回 | 时序交互图（`kind: sequence`） |
| 有哪些接口与实现、实现/关联关系怎么走 | 类图（`kind: class`） |
| 一个流程跨了哪几个责任方、在谁那里交接 | 泳道图（`kind: swimlane`） |

一张图只答一个问题；答两件事就拆图。**不适用**：高保真 UI 原型、炫酷汇报封面、纯业务流程（用 BPMN 更合适）、状态机 / 桑基图 / 甘特图 / C4 / 数据图（本技能没有对应基元，见 §九）。

## 五、反模式（不要这么做）

- ❌ 渐变、阴影、3D、立体盒子——破坏扁平白底感
- ❌ 中文用衬线/艺术字体——一律无衬线
- ❌ 颜色花哨或同类组件不同色——颜色只用于分类
- ❌ 粗描边/粗箭头抢戏——一律 1px 细线小箭头
- ❌ 存储不用圆柱、混用怪形状——DB 必须用 `cylinder`
- ❌ 节点过多无留白——宁可拆多张图，也不要塞爆
- ❌ 缺分组、缺标注——关系靠虚线框，要点靠便签钉出来
- ❌ 箭头被节点 / 分组标题 / 连线标签白底 / 便签盖住——箭头层必须在最上
- ❌ 从上方下来、明明能一条直线指向方框，却中间横折一下——无意义折点，必须删

## 六、与生成器的对应关系

`scripts/gen_diagram.py` 把上面每一条落成参数，**坐标自由摆放**：

| 规范条目 | 生成器字段 |
|---|---|
| 圆角矩形模块 | `nodes[]`（默认 `shape: rect`，`fill` 取上表 token） |
| 圆柱存储 | `nodes[]` 设 `"shape": "cylinder"` |
| 便签标注 | `callouts[]`（贴在一旁的小黄块） |
| 虚线分组 | `groups[]`（`nodes` 列表 + `title` + `stroke` + `fill` 浅色底） |
| 层级虚线分隔 | `tiers[]`（可选，`{"y":数值,"label":"层级名 · 说明"}`） |
| 鹰眼监控列 | `monitor`（可选，`{"label":"鹰眼"}`） |
| 正交连线 | `edges[]`（`from`/`to`/`color`/`dashed`/`label`/`route:"v"\\|"h"` 可选强制方向；`straight:true` 强制直连、`false` 允许端口错开折一次） |
| 背景面板 | `panels[]`（可选大色块底） |
| 标题/副标题 | `meta.title` / `meta.subtitle` |
| 配色覆盖 | `palette`（可选，覆盖/新增 token） |

照着 `assets/diagram.example.json` 改 `nodes` / `edges` / `groups` 的坐标即可，无需手写 SVG。

## 七、动笔前的三问（借来的判断顺序）

> 做法来源：本地已装的 `smart-arch-diagram`（仅借鉴其判断顺序，未复制其文本与代码）。
> 它的三条不变式是：**解引用一切 / 论证而非展示 / 一图一主题**。
> 落到本技能，变成动笔前必须先答的三句话——答不出就别开生成器。

1. **一图一主题：这张图回答哪一个问题？**
   用一句话写下来，写进 `meta.subtitle`。写不出，说明你想说的其实是两件事，拆图。
   反例：把「架构总览 + 部署拓扑 + 调用时序」塞进一张图，读者只会记住它很满。

2. **论证而非展示：每条连线能不能复述成一句话？**
   格式是「A 因为 X，把 Y 交给 B」。复述不出来的线，多半只是为了好看，删掉。
   这一条专治「画了一堆箭头却说不清数据流向」的图。

3. **解引用一切：图里的名词在图内能看懂吗？**
   `CK`、`progress.md`、`五项`、`04 边界` 这类词，要么图内有定义，要么正文紧邻处有定义。
   读者不该为了看懂一张图，去翻前面三千字。

## 八、出图后的自检清单（逐条过，全过才算完）

按顺序看，每条都对应一次真实返工：

- [ ] **便签被裁了吗** —— 最底部 / 最右侧的便签是否完整。自动画布曾漏算 `callouts` 包围盒（已修），
      但 `canvas` 只放大不缩小，手填过小的高度仍会裁。
- [ ] **有没有跨整图的长回写线** —— 从最右拉回最左的那种线会横穿所有分组。
      改法：把「回写」画成层内循环，或拆成上下两层（写入层 / 取用层）。
- [ ] **双向边 + 虚线标签叠字了吗** —— A→B 与 B→A 同时存在时，两条标签必压在一起。
      改法：留主方向单链，反向关系写成一句 callout。
- [ ] **多节点汇流是不是竖排缠线了** —— 五个节点竖排再汇入一个框，线会绞成一团。
      改法：改横排，各自向下汇入同一个判定节点，差异用小标签标。
- [ ] **标签语义和节点对得上吗** —— 曾把 `04 边界` 下面的标签写成「何时停」，与 `05 停止条件` 撞车。
      逐对读一遍：节点说什么，标签就该说什么。
- [ ] **同一概念跨图同名吗** —— 同一份文档里，`原始事件流` 不要一处叫「日志」一处叫「流水」。
      先定词表，再画图。
- [ ] **2x 出图后还看得清吗** —— 渲染成 2 倍 PNG 放进文章，字号小于 11px 的标签会糊。
      标签能短则短，不要靠缩小字号塞字。
- [ ] **有两条线走在同一段路上吗** —— 重合的线看起来是一条粗线，或者在后半段「断掉」。
      生成器结束时会打印 `!! 连线重合 N 处`，看到就改：调坐标 / 加 `via` / 改 `buses`。
- [ ] **有线穿过方框吗** —— 节点画在连线主体之上，穿过的线会被整段遮住，只剩箭头孤零零悬着。
      典型死结：2×2 布局里，顶层框连第二排必然穿过第一排。这不是渲染问题，是布局问题，改布局。
      生成器收尾会打印 `!! 连线穿过节点 N 处`，按提示逐条改。
- [ ] **便签压在线上吗** —— 便签画在最上层，压在线上会把线切断。把便签挪到线的空隙，
      或挪到节点下方/上方不与支线相交的位置。
- [ ] **箭头被盖住了吗** —— 逐支看小三角：节点、分组标题、连线标签白底、便签、图题都不许压住它。
      生成器已把箭头层提到最上；手画 / 评审别人的图要自己保证，看到被盖就挪开遮挡物。
- [ ] **有「能直下却折一下」的线吗** —— 上下对齐的两盒之间出现「竖 → 横 → 竖」就是多余折点。
      生成器会打印 `!! 多余折线 N 处`；改坐标、删掉 `via` 里的冗余路点，或设 `straight:true`。
      回归样例：`cases/arrows_regression.png`（两条直连 + 一条必要的斜向折）。

## 九、数据图（两个生成器都不覆盖）

折线 / U 型曲线 / 柱状 / 散点，两个生成器都没有对应基元（架构图只有节点、连线、分组、便签；扩展图种只有生命线、类框、泳道）。
这类图**手写 SVG**，但必须沿用同一套视觉，否则同一篇文章里像两个人画的：

| 要素 | 取值 |
|---|---|
| 背景 | 纯白 `#ffffff`，不加卡片底、不加阴影 |
| 标题 / 副标题 | 与 `meta` 同款：26px 加粗黑 + 14px `#888`，左上角同一位置 |
| 主色 | 沿用 draw.io 调色板：蓝 `#1ba1e2`、石板 `#647687`、橙 `#fa6800`、绿 `#60a917`、红 `#FF3333` |
| 网格 / 坐标轴 | 1px `#e3e6e9` 细线，不画刻度块 |
| 字号 | 轴标签 13px、注释 12~13px、关键数字可到 20px |
| 字体 | 与生成器一致的无衬线栈 |

最小骨架（换数据即可）：

```python
def svg_shell(w, h, title, subtitle, body):
    return (f'<svg xmlns="http://www.w3.org/2000/svg" width="{w}" height="{h}" '
            f'viewBox="0 0 {w} {h}"><rect width="{w}" height="{h}" fill="#fff"/>'
            f'<text x="40" y="46" font-size="26" font-weight="700">{title}</text>'
            f'<text x="40" y="70" font-size="14" fill="#888">{subtitle}</text>'
            f'{body}</svg>')
```

画完同样走 §八 的清单——数据图最常犯的是「标签压线」和「轴标签被裁」。

## 十、布线：三档手段，从便宜到贵

连线的默认行为是自动正交路由（上下分离竖进竖出、并排横进横出；**能直连就一条直线，绝不无意义折一下**）。
自动布线解决不了的情况，按下面顺序升级手段，**别一上来就手算坐标**。

### 第一档：什么都不写（先试这个）

能自动就自动。规则已经处理了：端口错开、跨线桥（白晕切断）、标签避让、**直连优先**（两盒有公共对齐区间就输出两点直线、共线冗余拐点自动合并）、**箭头层置顶**。
只有斜对角、多线抢端口、或必须绕开节点时才会折——那种折是必要的，别手工抹平。

什么时候不够用：线必须穿过别的节点、环状图的回退边、跨层的长线。

### 第二档：`edges[].via` —— 给几个拐点

```json
{"from": "v4", "to": "v2", "via": [[595, 314], [595, 230], [445, 230]], "label": "再验"}
```

- 起止端口**自动**取「朝向首个/末个路点」的那条边，不用自己算节点边缘；目标端固定留 8px，箭头不会被目标盒描边吃掉。
- 路点之间会自动正交化（缺拐点就补一个，先水平后垂直），共线冗余点自动合并。
- **别用 via 制造假折**：一条直线能到的，别写两个路点横挪一下。路点只用来「绕开节点」，不是用来装饰。
- 路点坐标和节点一样会跟着整体平移，**不用手工补偿**。
- 典型用法：环状图的回退边走内圈（避开主干）、跨层连线走右侧空白通道。

判断标准：**这条线在图上必须「绕过去」而不是「穿过去」时，就用 via。**

### 第三档：`buses` —— 多线并一

```json
{"from": ["k1", "k2", "k3", "k4", "k5"], "to": "ok", "color": "#5a5a5a"}
{"from": "p0", "to": ["p1", "p2", "p3", "p4"]}
```

- 一侧数组、另一侧单个 → 自动判断汇流（多→1）还是分流（1→多）。
- 效果：N 条平行线 → **1 根主干 + N 条短支线**，视觉上从「五条线挤成一束」变成「一个汇流口」。
- 可选参数：`y`（汇流主干的水平位置）、`x`（分流主干的竖直位置）、`entry`（进目标时的落点 x/y）。
- 什么时候必须用：**≥3 条线指向同一目标**，或一个源扇出到 ≥3 个目标。
  这种情况下自动布线的端口偏移（24px 一档）在窄节点上会被挤到一起，必然重合。

### 别用总线掩盖布局问题

`buses` 是「结构上本来就是多对一」的表达，不是给烂布局擦屁股的。
如果两个框的 x 范围完全重叠、连线必须穿过对方（2×2 里连第二排），那是布局错了：
改成「左输入 → 右竖排」或「横排一行」，比加总线干净得多。

## 十一、扩展图种（时序 / 类 / 泳道）

`scripts/gen_diagram_ext.py` 补了三种图，但**不另立视觉**。它直接 `import gen_diagram`，
复用 `THEME`（draw.io 默认调色板）、`F` 字体栈、`esc`、`_est_text_w`、`_ortho_join`（去假折）、
`_elems` / `_tip_elems`（白晕 + 箭头层）。所以同一篇文章里四张图像一个人画的。

### 不变的六条（四种图都要过）

1. **纯白底 + 扁平**，无渐变 / 阴影 / 3D。
2. **色板只用 `THEME` 的 token**，实心重色配白字、浅色配黑字；同一语义全图同色。
3. **标题左上角** 26px 加粗、副标题 14px 灰字，位置四张图一致。
4. **主体线在下、箭头层在最上**：末段 + 小三角最后重画，节点 / 分组标题 / 标签白底 / 便签 / 图题都不许盖住箭头。
5. **能直连就不折**：两点共线就出两点直线；`_ortho_join` 会清掉共线冗余拐点。
6. **标签白底只用来压线，不用来盖内容**；标签落在外侧空白处，不能压住框、折返段或别的文字。

### ① 时序交互图 `kind: sequence`

| 基元 | 画法 |
|---|---|
| 参与者头框 | 顶部横排圆角矩形，配色 token 与架构图节点一致 |
| 生命线 | 头框下方灰色虚线，贯穿全图 |
| 消息 | 实线 = 调用 / 数据流；虚线 = 返回 / 回写；`from == to` 画右侧 U 形自调用 |
| 激活条 | 生命线上 12px 窄条，表示「该组件正在处理」，用浅色 token |
| 组合框 | `frames[]` 虚线圆角框 + `loop` / `opt` 标题，圈住一段消息行 |
| 便签 | `messages[].note` 浅黄块，贴在消息行下方 |

**专属反模式**：
- ❌ 组合框标题先画 —— 会被生命线、激活条、消息线白晕吃掉最后一个字。**标题必须最后落笔**。
- ❌ 自调用标签压在 U 形竖线上 —— 白底会把折返段切掉一截，标签要放竖线外侧。
- ❌ 激活条起点早于组合框标题所在行 —— 标题白底会在激活条上切一个缺口，起点对齐 `frames[].from`。
- ❌ 返回消息画实线 —— 返回 / 回写一律虚线 + 小箭头。
- ❌ 消息标签写成长句 —— 列宽有限，超过约 18 字就该拆成 `note`。

### ② 类图 `kind: class`

| 基元 | 画法 |
|---|---|
| 类框 | 三段式圆角矩形：标题条（配色 token 实心/浅色）、字段区、方法区，中间一条细分隔线 |
| 接口 | `stereotype: interface` → 标题写 `«interface» Ixxx` |
| 实现 | `relations[].kind: realize` → 虚线 + **空心三角**，三角指向接口 |
| 关联 / 依赖 | 实线小箭头（依赖可虚线），标签写「谁因为什么把什么交给谁」的简写 |
| 分组 | 浅色底 + 虚线圆角框 + 标题（接口层 / 实现层 / 数据层），与架构图 `groups[]` 同款 |

**专属反模式**：
- ❌ 实心三角表示实现 —— UML 里那是继承/泛化，实现接口必须是**空心**三角 + 虚线。
- ❌ 关系线压在类框上 —— 主体线画在类框之下，只有箭头层在上。
- ❌ 同列 / 同行两框之间还折一下 —— 中心 x 或 y 对齐就出一条直线。
- ❌ 字段 / 方法塞超过框高 —— 每个类框按 18px 行高留够高度，宁可拆图。

### ③ 泳道图 `kind: swimlane`

| 基元 | 画法 |
|---|---|
| 泳道 | 等宽竖列 + 交替极浅底 + 顶部实心标题条，一列 = 一个责任方 |
| 步骤框 | 圆角矩形 + 左侧序号圆点，自上而下编号，框内一句话说清动作 |
| 层内流转 | **一条竖直线**，不折 |
| 跨层交接 | 只折一次（V-H-V），标签落在水平段外侧空白 |

**专属反模式**：
- ❌ 同一泳道内还横挪一下 —— 那是假折，直接竖线到底。
- ❌ 步骤文字超过列宽 —— 缩短措辞，别缩字号（低于 12px 的标签 2× 出图会糊）。
- ❌ 跨层折线穿过步骤框 —— 折点落在两行之间的空隙，端点留 8px。
- ❌ 四条泳道四种重色 —— 标题条可以分色，步骤框优先统一浅色，颜色只用于分类。

### 出图自检（在 §八 清单之上再加四条）

- [ ] 四种图的标题位置、字号、配色 token 是否一致（放在一起看是不是一套）。
- [ ] 时序组合框标题、类图空心三角、泳道序号圆点是否完整可见、没被白底/激活条切掉。
- [ ] 每张图是否只回答了一个问题（`meta.subtitle` 写得出来）。
- [ ] 箭头末段是否都在最上层，逐支看过小三角。

**完整范例**：仓库 `examples/zinx_{arch,sequence,class,swimlane}.json` + `cases/` 下四张预览图，
同一个 Zinx 项目画出四种图，改坐标与文案即可复用。
