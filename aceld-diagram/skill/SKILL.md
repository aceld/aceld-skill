# Aceld 架构图绘制 · draw.io 默认主题白底扁平风

把刘丹冰(Aceld) 多年沉淀的「架构图怎么画」变成可复用的技能。核心是**用最小可视化成本讲清系统怎么跑、数据怎么流、关键节点在哪**——纯白底、扁平、不追求花哨，追求一眼读懂。风格提取自其 `鹰眼二期` / `KisFlow` 等 `.drawio` 源文件真实配色与图形，而非主观想象。

**本技能覆盖不了**：时序图 / 状态机 / 桑基图 / 甘特图 —— 遇到直接走 ②，别用矩形硬拼。
**同样覆盖不了数据图**（折线 / U 型曲线 / 柱状 / 散点）：生成器只有节点、连线、分组、便签四种基元。

## 0. 一句话定位

Aceld 的图是**白底、扁平、draw.io 默认主题**的：圆角矩形模块（1px 同色描边）、圆柱做存储、虚线框分组、便签做标注、细线小箭头、**左侧蓝色「鹰眼」监控列**纵贯全图。颜色取自 draw.io 内置调色板，同类语义同色。

**版式默认竖版**（文档多为「高不限、宽有限」，约 4:5~3:4 最易嵌入文章/讲义，不会被横向裁切）；大屏/PPT 才用横版。两种版式共用同一份 spec，只改坐标与 `canvas` 宽高：竖版缩窄模块宽度、拉大层间纵向间距、存储放最底部横排，拓扑不变。

## 1. 核心风格清单（画之前先记住）

1. **纯白底 + 扁平 + 零装饰**（无渐变/阴影/3D）。
2. **圆角矩形模块**（`rounded=1`）：1px 描边取同色系深一档；中文+英文混排、居中无衬线。
3. **配色用 draw.io 默认调色板**：蓝 `#1ba1e2`、绿 `#d5e8d4`、浅蓝 `#dae8fc`、红 `#f8cecc`、黄 `#fff2cc`、灰 `#E6E6E6`、石板蓝 `#647687`、橙 `#fa6800`、紫 `#e1d5e7`… 同类语义全图同色。**同一张图只在一种色系内选，且优先全实心重色**（blue/orange/slate/sgreen/crimson/dark 白字）；若用浅色则必须全浅色，深浅绝不混搭。详见 `references/style-guide.md`。
4. **数据库一律用圆柱**（`cylinder`）：MySQL / Redis / 日志存储等，浅色填充+同色描边。
5. **虚线分组括号 + 标题 + 浅色底**：相关模块用**浅色底 + 同色虚线圆角框**圈起并加标题（如 `Function 算子池`、`调度核心`、`外部依赖`）；不同分组用不同色相的极浅色，形成清晰层级感；所有分组**默认等宽**（取并集左右界），上下堆叠成整齐层带。
6. **层级虚线分隔（tiers）**：表达「分了几层 / 每层是什么」时，用贯穿全图的横向虚线划层，左端写加粗层级名 + 一句话说明（如 `算子执行层 · 算子可插拔、配置热更新`）；不要用零散便签标「算子可插拔/配置热更新」之类——层级语义一律用虚线分隔 + 文本描述。
7. **便签（note）做标注**：补充说明贴在一旁，浅黄底小折角块。
8. **左侧跨维度列（可选，非默认）**：仅当图里确有「跨维度全局模块 / 关注点」（全局配置、监控、安全、统一接口层等）时，才用最左侧纵贯竖条承载其标签（逐字换行、不旋转）。**「鹰眼」只是鹰眼二期那张图的具体实例，不是 Aceld 风格的固定符号——换图要换名，或干脆不加。**
9. **正交连线 + 小三角箭头**：线略粗（~2.2px）、箭头小而克制。**上下分离→竖进竖出**（A 在 B 上方就竖直出入，不从侧边绕），同行并排才横进横出；端点留隙（头 3px / 箭 8px）使整支箭头落在盒外；**连线主体画在节点之下**（跨盒时被遮住，不盖住别的模块），但**箭头末段单独提到最上层**（第 13 条）；同边多线自动错开端口；逐条「白晕→彩线」形成**跨线桥**；连线标签自动避开节点/标题/其它标签。实线表主数据流，虚线表控制/依赖（如 `调度`、`管理`、`连接`）。
10. **自由摆放、多图岛**：模块是手摆坐标而非自动布局；一张图可有多个相对独立的子系统，靠分组框区分。
11. **顺序链可用 chevron/step**：折角箭头块或起止圆表达处理顺序。
12. **连线不许重合、不许穿节点**：两条线走同一段路，看起来就是一条粗线或一条断线；线穿过方框会被节点盖掉，只剩箭头孤零零悬着。生成器收尾会打印 `!! 连线重合 N 处` / `!! 连线穿过节点 N 处`，**看到就改**：调坐标、加 `via` 绕行，或改用 `buses` 合并。
13. **箭头永不被覆盖**（2026-11-05 定）：节点、连线标签白底、分组虚线框与标题、便签、图题**全画在主体线之上**，箭头若跟着主体线走就必然被压掉。生成器把「末段 18px + 箭头」拆成独立**箭头层**，在所有元素之后重画——主体线仍在节点之下（不破坏「线不盖盒」），箭头永远可见。显式 `via` 的目标端也留 8px（早期只留 3px，箭头尖贴着盒边被描边吃掉）。手绘或评审别人的图同标准：**任何元素压住箭头都算错**，优先挪开遮挡物，不是把箭头缩回盒里。
14. **能直连就不折**（2026-11-05 定）：A 在 B 正上方、两盒 x 区间有交集时，**一条竖线直达 B 盒顶**，禁止「竖下→横挪一点→再竖下」的假折；同行并排、两盒 y 区间有交集时同理走一条横线。只有三种情况允许折：①两盒斜对角、x/y 完全错开；②同一条边挂了多条线、端口必须错开；③显式 `via` 绕开节点。生成器默认自动直连，`straight:true` 强制、`straight:false` 禁用，并清掉路径里的共线冗余拐点；打印 `!! 多余折线 N 处` 就是这条规则被破坏，看到就改坐标。

## 2. 两种用法

### 用法 A：自动生成（推荐，按坐标摆放）

编辑一份声明式 spec（JSON 即可，YAML 需装 PyYAML），运行生成器产出 SVG/HTML：

```bash
# 路径相对于本技能目录（skills/aceld-diagram/）
python scripts/gen_diagram.py assets/diagram.example.json -o out.html
# 同时得到 out.html（浏览器看）和 out.svg
```

spec 字段（坐标自由摆放，详见 `assets/diagram.example.json`）：

| 字段 | 作用 |
|---|---|
| `meta.title` / `meta.subtitle` | 标题 / 副标题 |
| `monitor` | 左侧跨维度列 `{label}`（可选，非默认；`label` 写该图的全局/横切模块名，**不是固定「鹰眼」**） |
| `nodes[]` | 模块：`{id,x,y,w,h,fill(配色token),shape(rect\|cylinder\|note\|circle),label,fontSize,bold}` |
| `groups[]` | 虚线分组：`{nodes:[id...], title, stroke, fill}`（`fill` 为浅色底） |
| `tiers[]` | 层级虚线分隔（可选）：`{y:数值, label:"层级名 · 说明"}` |
| `edges[]` | 连线：`{from,to,color,dashed,label,route,via,straight}`（`route:"v"/"h"` 可强制竖直/水平；默认按上下/并排自动判断并**优先直连**；`straight:true` 强制一条直线、`false` 允许端口错开折一次；自动算端口 + 小箭头；箭头层置顶；`via:[[x,y],…]` 给显式路点，绕开节点用） |
| `buses[]` | 总线：`{from,to,color,dashed,label,y,x,entry}`。`from` 或 `to` 有一侧写成数组 → 多线并成一主干（汇流/分流），根治「N 条平行线贴在一起」 |
| `callouts[]` | 便签标注：`{at:[x,y], text, color}` |
| `panels[]` | 背景大色块：`{x,y,w,h,fill,label}`（可选） |
| `palette` | 覆盖/新增配色 token（可选） |
| `canvas` | 画布 `{width,height}`（可选）。只放大不缩小；便签/分组贴边时用它兜底留白 |

`fill` 取 style-guide 的配色 token（如 `blue/green/lblue/red/yellow/slate/orange/purple/gray`）；实心深色（`blue/orange/slate/sgreen`）自动配白字，浅色配黑字。改坐标与字段即可，**无需手写 SVG**。

### 用法 B：按规范手绘 / 指导

当需要口述或手画时，照 `references/style-guide.md` 的清单与反模式执行：白底、圆角矩形、圆柱存储、虚线分组、便签标注、鹰眼监控列、细线小箭头。

## 3. 决策树

```
用户要画图？
├─ 能给出组件/依赖清单 → 用法 A：写 JSON spec（nodes/edges/groups）跑生成器
├─ 只是想看「Aceld 风格长啥样」→ 跑 assets/diagram.example.json，看产出的 html
└─ 要手画 / 评审一张图 → 用法 B：按 style-guide 清单核对
```

## 4. 反模式（不要做）

❌ 渐变/阴影/3D ❌ 中文衬线字体 ❌ 同类组件不同色 ❌ 粗描边/粗箭头抢戏
❌ 存储不用圆柱 ❌ 一张图塞爆（宁可拆多张）❌ 关系不分组、要点不标便签
❌ 箭头被节点 / 分组标题 / 便签盖住 ❌ 能直下却绕一个 Z 形折（无意义折点）

## 6. 能力缺口 → 动态找技能

本技能覆盖的是「静态架构图」。遇到下面这些信号，**不要硬画**，先去网上找：

| 信号 | 例子 |
|---|---|
| 要画的图形类型本技能没有 | 时序图、状态机、桑基图、甘特图、C4 模型 |
| 想要另一种风格 | 手绘风、暗色风、等距 3D、极简黑白 |
| 反复调不好 | 布局挤在一起调了半小时还挤 |

流程（由 `aceld-findskill` 技能提供）：

1. **写缺口** —— 一句话说清「输入 → 期望输出 → 约束」
   （例：一份 API 调用流程 → 时序图 SVG，白底扁平风，与现有架构图配色一致）
2. **检索** —— `python ~/.workbuddy-ai/skills/aceld-findskill/scripts/find.py "sequence diagram"`
3. **体检** —— `vet.py owner/repo/skill`：五条硬性淘汰线 + 安全扫描，`REJECT` 的一律不用
4. **吸收** —— 只拿「方法论与检查清单」，生成器按本技能的约定重写；**不复制别人的代码与原文**
5. **回写** —— 补进 `references/style-guide.md`，并在 `SOURCES.md` 登记来源与 commit

三条不许破：**不自动安装 / 不搬代码 / 没扫过安全的技能当恶意对待**。

判断标准很简单：**如果这一步你在硬写一个自己没把握的实现，就是该去找技能的信号。**
