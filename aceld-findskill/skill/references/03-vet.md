# 03 · 硬性淘汰线与打分

> 五条线是**筛子**，不是评分表。任何一条不过就直接扔，别「综合考量」——
> 综合考量的结果通常是花两小时读了一个不该用的技能。

---

## 1. 五条硬性淘汰线

### 线 1：`SKILL.md` frontmatter 合法

```yaml
---
name: pdf                      # 必填，小写字母数字 + 连字符，≤64 字符，等于目录名
description: Use this skill…    # 必填，1–1024 字符，第三人称，含触发关键词
license: MIT                    # 可选
compatibility: …                # 可选
allowed-tools: Read, Bash       # 可选
---
```

| 不过的情况 | 后果 |
|---|---|
| `name` 带大写/下划线/空格 | 部分 Agent 加载不到 |
| `name` 与目录名不一致 | 装上去目录名对不上，调用找不到 |
| `description` 写成第一人称「I can help you…」 | 语义检索命中率显著下降 |
| `description` 里没有触发关键词 | Agent 不知道什么时候该用它 |
| 没有 frontmatter | 直接不是合法技能 |

`description` 的写法对比：

```yaml
✗ description: 一个很好的 PDF 处理工具，我写了很多功能。
✓ description: Extract text and tables from PDFs, fill PDF forms, merge or split
   PDF files. Use when the user asks to read, combine, split, or fill a PDF.
```

**关键词要覆盖用户会说的原话**（"read a PDF" / "fill a form"），不是覆盖功能名。

### 线 2：许可明确

| 许可 | 判定 | 能做什么 |
|---|---|---|
| MIT / Apache-2.0 / BSD / ISC / MPL-2.0 / Unlicense / CC0 | ✅ ok | 读、改、搬代码都行（保留声明） |
| GPL / AGPL | ⚠️ warn | 可读可改写；**分发改写版要同许可**（AGPL 连 SaaS 也算分发） |
| 无 LICENSE / `NOASSERTION` | ⚠️ warn | **只能读方法，不能复制代码与原文** |
| CC-BY-NC / CC-BY-ND / SSPL / BUSL | ❌ reject | 不能吸收 |

**现实很骨感**：生态里安装量最高的两个仓库（`anthropics/skills` 专有、
`vercel-labs/agent-skills` 无许可）都不属于「随便抄」。所以本技能的铁律二才是
「吸收方法论，不搬代码」——既规避法律风险，也真的更好用。

### 线 3：仍在维护

近 12 个月有提交。技能生态变化极快（模型能力、CLI 参数、平台规则一年一轮），
一年不动的技能大概率已经在教过时的做法。

`vet.py` 用 `pushed_at`（最后推送时间）判断，不用 `updated_at`（后者会被 star 刷）。
私有/内部源可放宽到 24 个月。

### 线 4：有真实使用

`安装量 ≥ 1000` **或** `源仓库 ★ ≥ 100`。

为什么用「或」：新技能可能安装量还没起来，但出自大仓库；老仓库可能星标高但技能没人用。
两条都低就说明确实没人验证过。

内网/团队私有源可把两条都设为 0（此时靠线 3 + 线 5 兜）。

### 线 5：结构合规

| 检查 | 阈值 | 原因 |
|---|---|---|
| 正文行数 | < 500 行 | 超了说明该拆 reference |
| 正文 token | < 5000 | 上下文预算（元数据 ~100 token，正文是加载后立即消耗的） |
| 引用深度 | 只一层（`references/x.md`，不能再指向 `references/y.md`） | 二级引用会被 Agent 忽略 |
| 绝对路径 | 无（`C:\...`、`/Users/...`、`/home/...`） | 换机器就废 |

## 2. 通过之后的打分（决定先读哪个）

不是精确评分，只是排序依据：

| 维度 | 权重 | 判断 |
|---|---|---|
| 安装量档位 | 30% | >10 万 30 / 1–10 万 22 / 1 千–1 万 15 / <1 千 5 |
| 与我们缺口的贴合度 | 30% | 一句话能否直接对上「输入→输出」（对上 30，部分 15，勉强 5） |
| 方法可迁移性 | 20% | 全是平台绑定的脚本 → 低；有检查清单/判断顺序 → 高 |
| 结构质量 | 10% | frontmatter 规范、有 references 分层、有反例 |
| 维护活跃 | 10% | 近 3 个月有提交 10 / 半年内 6 / 一年内 3 |

**贴合度必须排第一顺位看**：安装量 80 万的「Web 设计规范」技能，
对「竖版视频版式重排」这个缺口可能一分不值。

## 3. 四种「看起来很好其实不能用」

| 症状 | 真相 |
|---|---|
| 星标很高，正文 30 行，全是 `see https://...` | 是**索引**不是技能，读它等于读一堆链接 |
| 正文全是脚本调用，没有判断逻辑 | 换环境就废，没有可吸收的方法论 |
| 只支持某个平台（某家云、某个 IDE） | 你的场景对不上，改造成本高于自己写 |
| 安装量很高但近两年没更新 | 曾经好用，现在参数/接口全变了 |
| `description` 写得像广告 | 通常是刷榜或 AI 批量生成的，正文往往空 |

            ├─ 只有许可一条不过 → 可以「读」但绝不复制代码/原文

            └─ 其他              → 找下一个候选，别硬救
