# 公众号文章写作规范

写给技术类长文。目标读者是**能看懂代码、但没时间读论文**的工程师。

---

## 一、标题

三种能用：

1. **系列 + 课次 + 副题 + 一句钩子**
   `凡人AI修仙（第六课）：守心之道 —— 智能体长任务，为什么不跑偏`
2. **反常识判断**
   `你的 Agent 不是不聪明，是跑久了会偏`
3. **数字 + 具体承诺**
   `五种死法、三层病机、五道闸门：长任务不跑偏的完整清单`

不要用：「浅谈」「漫谈」「一文读懂」（烂大街）、纯疑问句（`如何做好 X？`）。

副标题里的数字要和正文对得上。写了「12 张架构图」，正文就得有 12 张。

---

## 二、开篇（前 300 字决定留存）

固定三段式：

1. **接上一篇**：一句话说清「前面解决了什么」
2. **转折**：指出它没解决的问题（这是本篇的存在理由）
3. **给结论**：本篇要立的判断，先说出来，别憋到最后

示例（第六课实际用的）：

> 前面五课，我们一直在解决「它能不能干完」。这一课要讲的，是另一件事——
> 真正让智能体干不成活的，往往不是它不够聪明，是它**跑久了会偏**。

**禁止**开头写「随着人工智能的快速发展」「在当今时代」。

---

## 三、主体结构：现象 → 病机 → 解法

这是长文最稳的骨架，读者不会迷路。

```
01 开场        为什么单独拿这一课讲这件事
02 现象        列出现场：五种死法 / 五个失败案例（越具体越好）
03 病机        归因：三层，每层一句话结论 + 展开
04 解法        每层对应一道闸门，能落地、能验证
05 收尾        回顾 + 预告 + 互动
```

**关键：现象和解法必须一一对应。** 前面列了五个死法，后面就得有五个对应手段，
读者会数。对不上就是结构塌了。

### 每节的写法

```markdown
## 三、病机：三种走偏的方式

（导语块：一句话结论，加粗）

### 3.1 上下文失真

第一段直接给判断，不要铺垫。

展开：为什么会这样 → 具体机制 → 一个能复现的例子。

![图注写这张图在说什么，不写"架构图"](文章配图/v2/fig03.png)

收束一句：所以这一层的闸门是「外部记忆」。
```

**导语块**（小节第一段）在排版时会渲染成左侧竖条的浅底卡片，
作用是「先给结论再展开」。第一段别写过渡句，直接上判断。

---

## 四、配图节奏

- 每 **800～1200 字**一张，长文 20 分钟内读完的话 8～14 张合适
- 图必须**承载信息**，不能只是装饰：架构、流程、对比、时间线
- 图注写「这张图说明了什么」，不写「图 3 架构图」
- 图和正文要能互相替代：只看图能懂 70%，只看文字能懂 70%

图用 `aceld-diagram` 出白底扁平 draw.io 风，配色和文章主题同源（见 `assets/theme-aceld.json`）。

## 五、排版手法（都要在 markdown 里写，转换时自动渲染）

| 手法 | markdown 写法 | 用在哪 |
|---|---|---|
| 导语块 | 小节第一段（自动） | 每节开头给结论 |
| 重点高亮 | `==这句话==` | 全文不超过 8 处 |
| 加粗 | `**关键词**` | 判断句、转折词 |
| 引用块 | `> 多行` | 大段引用、金句、对话 |
| 对比表 | markdown 表格 | 方案对比、清单核对 |
| 分隔线 | `---` | 大章节之间 |

**加粗只加判断，不加名词。**
❌ `**智能体**需要**上下文**`
✅ `**它不是不够聪明，是跑久了会偏**`

## 六、语言：去 AI 味

AI 味的典型症状和改法：

| 症状 | 改法 |
|---|---|
| 「首先/其次/再次/最后」 | 删掉，用语义衔接 |
| 「总之/综上所述」 | 直接说结论 |
| 「让我们一起…」 | 删 |
| 「值得注意的是」 | 删，直接说 |
| 每段都三行等长 | 长短交错，一句话成段也行 |
| 通篇四字词 | 换成大白话 |
| 「极大地提升了」 | 给数字：`从 40 分钟压到 90 秒` |

**短句优先。** 一句话超过 40 字就拆。

**给数字，不给形容词。** 「很快」→「1.7 秒」；「很多」→「12 张图」。

**允许口语。** 「这个坑我踩了三次」「说白了就是」——比书面语更像人在讲。

---

## 七、收尾

三块，缺一不可：

1. **回顾**：把本篇立的几个东西列一遍（读者可能跳读，这里是补课）
2. **预告**：下一课讲什么，留一个具体的钩子
3. **互动**：一句自然的号召，别硬求关注

```markdown
## 写在最后

这一课我们把长任务的五道闸门立完了：目标锚、路书、验证环、外部记忆、权限结界。

## 下节预告

第七课《分身之道》——当一个智能体不够用，怎么让一群智能体协作而不打架。
```

- [ ] 现象和解法一一对应，数量对得上
- [ ] 每 800～1200 字有一张图，图注说信息不说类型

- [ ] 全文搜一遍「首先」「其次」「总之」「综上」「值得注意」，全删
- [ ] 结尾有回顾 + 预告 + 互动
- [ ] 配图路径能在 `文章配图/` 下找到，一张不缺
